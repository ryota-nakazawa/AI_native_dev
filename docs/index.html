エージェント化した開発フローとリグレッションテストを、動かしながら見る

Claude Code のサブエージェントに開発の各工程とテストケースを割り当て、どこが動いていて、どこでどれだけトークンを使ったかを画面に出した例です。実際に流した1回分の記録を、再生ボタンで何度でも見直せます。

開発フロー仕様整理 → 実装 → テスト → レビューの4工程。工程別のトークン量と、いつ動いたかの帯。約2分の記録 → リグレッションテスト6件を並列実行。進捗、PASS / FAIL、ケースごとの所要時間とトークン量。約20秒の記録 → エージェント別指揮役とサブエージェントの箱。モデルごとの使用量と、ツール呼び出しの流れ。約3分の記録 →

使い方

  • 各画面は、最初は実行が終わった状態で表示されます。画面下の ▶ 再生 を押すと最初から流れます。
  • 1× 3× 10× 30× で倍速を選べます。終わったら ↻ もう一度 で見直せます。
  • 箱と棒の色はモデルを表します（青 = Haiku、橙 = Sonnet、緑 = 指揮役のモデル）。

何を流した記録か

題材は、メモを保存するだけの小さな Web API です。「保存済みメモの一覧を返す機能を足す」という変更を4工程で通し、変更後の API に対してリグレッションテスト6件を並列で実行しました。1工程・1テストケースを、それぞれ1体のサブエージェントが担当しています。

工程 / テストモデル所要トークン結果
1. 仕様整理Haiku 5.50:34172k仕様書を作成
2. 実装Sonnet 5.50:22165k実装し、動作を確認
3. テストHaiku 5.50:47379k自動テスト12件が成功
4. レビューSonnet 5.50:17109k軽微な指摘4件
リグレッション 6件Haiku 5.5各 0:08〜0:12計 728k5件 PASS、1件 FAIL

トークンは、毎ターン読み直す入力（キャッシュ読み取りを含む）と出力の合計です。FAIL の1件は、落ちたときの見え方を示すために入れた、実際に満たされていない期待です。

この記録から読み取れたこと

  • 指揮役が全体の約7割を使っていた。文脈の大きいセッションが指揮すると、サブエージェントを1体起動するたびに全部を読み直すためです。指揮役は文脈の小さい専用セッションにするのが最初の改善になります。
  • 10秒で終わるテストに10万トークン以上かかっていた。大半は、エージェントが1往復ごとに読む初期文脈の固定費です。決まった手順の確認はスクリプトにし、エージェントは判断が要る箇所だけに使うほうが安くなります。
  • 工程ではテストが最も重かった。往復回数が多いほど増えるので、指示の出し方で減らせます。

仕組み

Claude Code が手元に残すセッション記録（メッセージとツール呼び出しが1行ずつ追記されるファイル）を読み、エージェント別に集計しています。エージェントの説明の先頭に flow:工程ID / case:ケースID という札を付け、報告の最終行の RESULT: PASS / RESULT: FAIL を合否として読みます。手元では実行中の様子をライブで表示でき、このページはその1回分を書き出したものです。

記録データに含まれる手元のファイルパスとセッション名は、公開用に置き換えています。
